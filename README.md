 # Investigating LLM-as-a-Judge for Explanation Evaluation

Master's thesis code and data accompanying the thesis:

> **Investigating LLM-as-a-Judge for Explanation Evaluation**
> Vanessa Urban, MSc — University of Vienna, 2026

The thesis investigates whether a Large Language Model acting as a Judge can
replace a human observer in a **simulatability** study, and whether input-level
feature attributions help the Judge identify which summary was produced by a
target model. The problem is framed as a **five-way summary attribution task**
on the [XSum](https://github.com/EdinburghNLP/XSum) dataset: the Judge must pick
the summary generated by **DistilBART-xsum-12-6** out of five candidates.

Full text available online at <https://utheses.univie.ac.at/detail/80709/>.

## Method overview

The experiment has two phases:

1. **Phase 1 — Baseline:** The Judge (Selene-1-Mini-Llama-3.1-8B) selects the
   target summary **without** any explanation.
2. **Phase 2 — With attributions:** The Judge receives **MExGen** feature
   attributions (top-1/top-2 sentence, or top phrase/top phrases) and selects again.

The difference in attribution accuracy between phases isolates the effect of
the explanations.

### Models and tools

| Component      | Model / Tool                                    |
|---------------|--------------------------------------------------|
| Target model   | DistilBART-xsum-12-6                            |
| Candidate model | Llama-3-8B-Instruct, Flan-T5-XL (plus human-written gold + human-written random summary) |
| Judge model    | Selene-1-Mini-Llama-3.1-8B                       |
| Attributions   | MExGen (C-LIME) via the ICX360 toolkit           |

Example selection for the few-shot prompts uses two strategies:
**embedding cosine similarity** and **k-means clustering** (see
`notebooks/CLOSE_IDX_(CLUSTER)_SIMILARITY.ipynb`).

### Order of execution

1. `INSTANCES_CANDIDATE_OUTPUTS.ipynb` — load XSum, generate DistilBART and other candidate summaries.
2. `CLOSE_IDX_(CLUSTER)_SIMILARITY.ipynb` — select few-shot prompt examples.
3. `EXAMPLES_MExGen.ipynb` — compute MExGen attributions.
4. `LLAMA_CONTRASTIVE_OUTPUTS.ipynb` — generate contrastive Llama summaries.
5. `judge_evals/` — run the Judge evaluations.

Each evaluation notebook contains two toggle cells near the top:

- `use_cluster_examples` — `False` = similarity-based examples, `True` = k-means cluster-based examples.
- `use_validation` — `False` = test set (200 instances), `True` = validation set (100 instances).

Set these before running; the notebooks load the matching `.pkl` files automatically.

## Reproducibility note

The candidate-to-letter (A–E) mapping in the judge loops is shuffled with
`random.shuffle(candidates)` and is **not** seeded, so the exact letter
assignments and therefore the raw per-instance outputs vary between runs.
